## Known limits of this inventory

Stated so they are not mistaken for completeness:

1. **Spring and server keys are excluded.** `server.*`, `spring.*` and
   `management.*` in the starter's `application.yaml` configure Spring Boot,
   Tomcat, Actuator and the datasource, not FHIR behaviour. Frevo must accept
   the ones that affect deployment (`server.port`, `server.servlet.context-path`,
   `spring.datasource.*`, the Actuator health and Prometheus endpoints) but
   they are tracked in the `frevo-config` capability, not row by row here.
2. **Spring relaxed binding is not enumerated.** Each key below is also
   settable as kebab-case, camelCase and as an environment variable. Which
   spellings must be supported is an open question in
   [`docs/capabilities/config.md`](capabilities/config.md).
3. **Operations reachable only through custom providers** (the starter's
   `custom_provider_classes`) cannot be enumerated: they are arbitrary Java.
   Frevo has no equivalent extension point and this is expected to be a
   documented gap.
4. **Per-operation parameters are not listed.** `$expand` alone takes more
   than a dozen. Those are enumerated in each capability's spec delta, where
   they get scenario ids.
5. **Pointcut counts include client-side and test pointcuts.** Triage happens
   when `frevo-server` is specified.
